## 2. 功能覆盖

- 登录：正确密码、错误密码、禁用账号、签名令牌和令牌篡改。
- 组队：容量、创建、Excel 编队、成员加入/移除、满员、重复入队、队长权限。
- 打卡：个人打卡、队伍完成进度、队长汇总、当天时段和全员完成校验。
- 上传：图片压缩后提交、格式白名单、文件签名、数量和大小限制、受保护下载。
- 活动广场：由公开队伍提交自动生成、隐藏、恢复、删除、分页和浏览统计。
- 点赞：点赞、取消、幂等、并发、每日上限。
- 排名：日榜、月榜、归一化热度、冻结和排名排除。
- 导出：用户、队伍、打卡、缺卡、排行榜、材料清单及未提交名单。

## 3. 异常覆盖

- 重复提交：最终提交后再次提交被拒绝。
- 并发提交：版本号冲突返回 `409`，不会静默覆盖。
- 超额点赞：超过每日额度被拒绝，并发请求不能绕过上限。
- 越权访问：普通用户访问管理员接口返回 `403`；用户不能读取其他用户的私有最终截图。
- 文件异常：错误扩展名、MIME/文件签名不一致、数量或大小超限被拒绝。
- 认证异常：篡改签名令牌返回 `401`；连续错误登录触发 `429`。

## 5. 700 用户压力结果

数据集包含 700 个独立学生账号并平均分配到四个校区。

### 同时登录

- 请求：700
- 成功：700
- 失败：0
- 总耗时：17.595 秒
- 吞吐：39.78 请求/秒
- P50：8.714 秒
- P95：16.358 秒
- P99：17.068 秒
- 最大：17.223 秒

密码使用 `scrypt` 验证，单机 Node 进程在所有用户同一瞬间登录时CPU串行排队明显。安全校验正常，但体验延迟不理想。

### 极端瞬时连接

700次登录刚结束后立即再创建700个并行读取连接，出现347个客户端连接级失败、353个HTTP 200。服务端没有返回业务错误，失败发生在本机连接资源层。该场景已保留为风险，没有通过修改业务逻辑掩盖。

## 6. 已解决问题

阶段11未修改业务功能。测试期间仅修正测试工具退出时Chrome临时目录被占用导致的清理失败；修正后设备矩阵重复执行通过。

以下既有问题在本轮得到回归确认：

- 普通用户不能访问管理员接口。
- 用户不能读取其他用户的私有最终截图。
- 并发提交不会覆盖已有记录。
- 并发点赞不能突破每日上限。
- 异常图片内容不能伪装成允许格式。
- 手机、平板、电脑和微信UA下学生核心页面没有横向溢出。

## 7. 未解决风险

1. 本地JSON数据库和本地磁盘不是Cloudflare生产数据层；尚未在D1和R2环境执行同等测试。
2. 700人完全同一瞬间登录时P95约16.4秒，虽无失败但体验偏慢。
3. 登录后立即再产生700个全新并行连接会触发本机连接失败；建议正式环境做渐进放量、连接复用和Cloudflare预览压测。
4. 未对700人同时上传5MB×8张图片进行破坏性压力测试；该测试可能产生28GB流量和大量临时对象，不适合在本地演示数据上执行。
5. 微信仅完成UA/WebView模拟，仍需至少一台Android微信和一台iOS微信进行真机上传、预览和下载验收。
6. Cloudflare免费版存在Workers每日请求量、CPU时间、D1行读写及R2操作额度；正式活动前应按真实访问模型重新核算。
