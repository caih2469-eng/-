# 项目现状与实施计划

## 1. 审计结论

当前仓库是一个可运行的本地原型，不是可直接部署到 Cloudflare Pages 的生产应用。项目没有被重建，本次检查也没有修改现有业务功能。

## 阶段 1 完成情况

阶段 1“用户资料和双赛道系统”已经完成：

- 用户资料增加姓名、学号、校区、所属赛道、账号状态和创建时间。
- 建立“四校区互动赛道”和“自律健康赛道”。
- 管理员可查看、添加、编辑、禁用/启用用户，并导入 `.xlsx` 名单。
- 普通用户只能通过 `/api/me` 查看自己的只读身份资料。
- 禁用账号不能重新登录，已有令牌也会失效。
- 旧 JSON 数据通过可重复执行的迁移补齐新字段，迁移前自动备份。
- 已增加登录、编辑、Excel 导入、禁用和越权访问自动测试。

### 已确认的结构

1. `public/index.html` 只提供挂载节点并加载 `style.css`、`app.js`。
2. `public/app.js` 通过字符串模板渲染宣传页、登录、学生打卡页和管理员后台。
3. `server.js` 同时提供静态文件、认证、打卡和管理员 API。
4. `data/db.json` 保存配置、用户和打卡记录。
5. `uploads/` 保存 Base64 解码后的图片文件。
6. `启动打卡网站.cmd` 在 Windows 上启动 Node 服务并打开 Edge。

## 2. 当前业务行为

- 账号由管理员创建，学生使用学号和密码登录。
- 服务端使用 Asia/Shanghai 时区判断当天日期和时间。
- 学生只能提交当天材料，并且只能在配置的早餐、午餐、晚餐窗口提交。
- 同一学生、日期和时段再次提交时，记录会被替换。
- 管理员可查看指定日期全部学生的提交状态，查看图片并通过或驳回。
- 管理员可修改活动名称和三个时段，可创建学生账号。

## 3. 当前主要问题

### P0：上线阻塞

- 密码仍以明文存储；阶段 1 已停止在 API 响应中返回密码字段。
- 登录令牌只是可伪造的 Base64 用户 ID，没有签名、过期时间或服务端会话。
- 内置管理员账号和默认密码已存在于公开仓库。
- 上传图片通过 `/uploads/...` 无鉴权公开访问。
- 没有 HTTPS、登录限流、密码修改/重置、会话吊销或审计日志。
- 本地 JSON 和文件系统不适用于 Cloudflare Pages，也无法保证多人并发写入安全。

### P1：数据可靠性和规则一致性

- `data/db.json` 是整文件读写；并发请求可能相互覆盖或造成文件损坏。
- 重新提交会删除旧记录，但不会删除旧图片，长期运行会产生孤立文件。
- `startDate`、`endDate` 只保存不执行，活动日期外仍可按时段打卡。
- 管理员配置没有严格字段校验，可提交不完整或异常结构。
- 宣传页的时段与“18天”等文案写死，管理员修改配置后不会同步。
- 管理员已可编辑、重置密码和禁用账号；仍没有删除账号功能。
- 被驳回记录在学生页面仍显示为“待审核”，状态表达不完整。

### P2：工程和可维护性

- 已增加 `package.json` 和 Node.js 自动测试；仍没有 TypeScript、ESLint、格式化、构建或 CI。
- 前后端代码高度压缩在少数长行中，审查和维护困难。
- `adminFor` 临时覆盖全局 `Date.prototype.toLocaleDateString`，异常时可能无法恢复。
- 前端采用 `innerHTML`；转义函数不覆盖引号，配置值进入属性时存在注入风险。
- 没有结构化日志、备份、数据导出、保留周期或故障恢复方案。

## 4. Cloudflare 与 GitHub 现状

### Cloudflare

仓库中不存在：

- `wrangler.toml` 或 `wrangler.jsonc`

## 5. 建议的后续实现方式

建议保留现有页面视觉和业务流程，分阶段迁移，不重建全部界面。

### 阶段 A：安全基线

1. 定义正式用户模型，密码使用强哈希；API 永不返回密码字段。
2. 使用签名、短时会话和 HttpOnly/Secure Cookie，增加退出和会话撤销。
3. 增加登录限流、权限中间件、输入校验和安全响应头。
4. 将上传图片改为受保护对象，管理员或所属学生经鉴权后访问。
5. 增加管理员首次初始化和强制修改密码流程。

### 阶段 B：Cloudflare 数据层

1. 将 API 迁移到 Cloudflare Workers 或 Pages Functions。
2. 使用 D1 保存用户、配置、打卡和审核记录。
3. 使用 R2 保存原图，D1 只保存对象键、元数据和状态。
4. 使用 Wrangler migrations 管理数据库结构。
5. 使用 Cloudflare Secrets 保存会话密钥，不写入仓库。

### 阶段 C：工程化和部署

1. 新增最小 `package.json`，定义 `dev`、`lint`、`typecheck`、`test`、`build`。
2. 在不改变页面功能的前提下逐步拆分前端和 API 模块。
3. 增加 API 单元测试、权限测试、时段边界测试和上传测试。
4. 配置 GitHub Actions 在 PR/推送时运行检查。
5. Cloudflare 先部署预览环境，验收后再绑定生产域名。

## 6. 上线验收门槛

- 不存在明文密码或可伪造令牌。
- 学生不能访问他人材料；未登录用户不能访问任何上传图片。
- 时段边界、活动日期、重复提交和审核状态均有自动测试。
- D1/R2 有备份和数据保留策略。
- GitHub CI 全部通过，Cloudflare 预览环境完成移动端和管理员验收。
