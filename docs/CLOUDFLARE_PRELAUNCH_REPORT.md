## 已解决问题

1. 旧 Node 压测器在 700 瞬时连接时卡在本机套接字/网络层，无法区分客户端
   限制和服务端失败。改用专用 HTTP/2 压测器后，700 个瞬时登录全部成功。
2. 登录改为 D1 唯一索引查找，不再扫描 JSON 用户数组。
3. 登录响应只返回会话和当前用户，不加载任务、队伍、广场及后台数据。
4. 用户读取使用主键查询；任务查询使用赛道、状态和时间索引。
5. 排行榜 700 瞬时查询最初有 48 个 500；改用公开 Cache API 60 秒缓存后，
   复测 700/700 成功。
6. 排行榜缓存仅用于公开榜单，不缓存用户资料、管理员数据或私有材料。
7. 测试及生产 D1 均已迁移；测试和生产 R2 私有桶均已创建并绑定。

## R2 真实上传和读取结果

测试使用 700 个不含个人信息的 5,000,000 字节 JPEG 测试体，总上传量
3,500,000,000 字节。并发数为 25，避免本机网络代理成为唯一瓶颈。

| 阶段 | 首轮结果 | P50 | P95 | P99 |
|---|---:|---:|---:|---:|
| R2 上传 | 696/700 | 20.78s | 38.41s | 47.78s |
| R2 读取 | 690/700 | 28.19s | 76.45s | 115.43s |

首轮 4 次上传失败均为测试机 `fetch failed`，没有 Cloudflare 5xx；首轮读取中
4 个 404 与缺失上传一一对应，另有 6 次本地超时或网络中断。随后仅对失败项
执行有限重试并逐个读取校验，最终确认：

- D1 中有 700 条上传记录；
- 记录总字节数为 3,500,000,000；
- 700 个对象均能完整读取为 5,000,000 字节；
- 测试对象、D1 压测记录和 `LOAD_TEST_SECRET` 已清理；
- 客户端只重试网络错误和 5xx，不重试 4xx。

## 700 瞬时连接结论

旧测试的 353 成功、347 失败不是 Cloudflare API 上限的直接证据。真实 Pages
Functions + D1 在专用客户端下完成了 700/700 瞬时登录。生产连接策略为：

- 浏览器使用 HTTPS/HTTP2 复用连接；
- 登录只执行一次索引查询和一次密码校验；
- 登录后各页面按需加载，不一次性获取所有业务数据；
- 公开排行榜走 Cache API；
- 图片流直接进入 R2，不在 Worker 中转成 Base64 或长期驻留内存；
- 不建立应用级数据库连接池，使用 D1 binding；
- 客户端只对网络中断和 5xx 做有限退避，不重试 4xx 或重复提交。

## 尚未完成和上线风险

### 阻塞项

1. **Cloudflare API 尚未与原 Node API 完全对等。** 当前测试 Function 只覆盖
   上线风险验证所需的登录、读取、排行榜和上传适配，不能替代全部业务接口。
   GitHub 生产部署已设置强制失败门禁。
2. **微信真实设备未验收。** UA 模拟不能证明 Android/iOS 微信的相册、拍照、
   HEIC、后台恢复和返回页面状态。
3. **GitHub 自动部署凭据需随新账号更新。** 仓库 Secrets 中的
   `CLOUDFLARE_ACCOUNT_ID` 和最小权限 API Token 仍需由账号持有人设置。

### 其他风险

- Cloudflare 免费版存在每日请求、D1 行读写和 R2 操作额度，活动高峰需观察
  Analytics；若接近配额应先降低无效轮询和重复刷新。
- R2 首轮大文件读取有明显长尾和本地网络中断；页面必须保留上传进度、有限
  重试和失败提示，不能把首轮客户端断线当作服务端记录成功。
- 700 瞬时登录新账号复测 P95 为 3.01 秒，已低于 5 秒目标。
- Pages.dev 在当前本地网络的 IPv6 路由不稳定；专用测试强制 IPv4 后稳定。
  正式域名需在校园网、移动网络和微信中分别验证 IPv4/IPv6。
- 生产库当前为空且活动开关关闭；正式用户导入、管理员初始化和数据核对尚需
  按受控流程完成。

## 结论

真实 D1 登录、读取和排行榜性能达到本阶段目标，真实 R2 完成了至少 3.5GB
上传、读取、失败恢复及元数据一致性验证。当前不能直接正式上线的原因不是
D1/R2 性能，而是完整业务 API 尚未全部迁移到 Cloudflare，以及微信真实设备
验收和 GitHub 新账号部署凭据尚未完成。
