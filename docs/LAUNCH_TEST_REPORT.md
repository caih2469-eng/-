# 正式上线前 Cloudflare 测试报告

测试日期：2026-07-26  
测试环境：`https://jinshan20-test.pages.dev`  
基础设施：Cloudflare Pages、Workers、测试 D1、测试 R2

## 结论

真实 Cloudflare 环境下，700 用户分批并发访问的任务、广场和排行榜查询全部成功；登录、常见压缩图片上传、私有图片读取和点赞各出现 1–3 个客户端连接超时，Cloudflare 业务接口没有返回 5xx。

目前可以进入小范围真实用户验收，但不建议直接宣布“700 人同一秒全部操作无风险”。单台发压机一次建立 700 个 TLS 连接时有 23.43% 连接层失败，且接近 5MB 的图片并发上传出现过一次 503。正式活动应依赖浏览器压缩，并避免组织所有参与者在同一秒刷新或上传。

## 上线风险

1. **极端同秒峰值：高。** 单机 700 瞬时连接未通过。活动通知应给出数分钟提交窗口，不要要求整点同一秒刷新。
2. **接近 5MB 图片：高。** 5MB 边界样本明显变慢并出现一次 503。前端通常会压缩到更小，但仍应重点观察高像素长截图。
3. **单点压测代表性：中。** 当前发压机位于同一网络、同一 IP；它比 700 台分布式手机更容易触发本地端口、链路或边缘防滥用限制。
4. **真实微信验收：中。** UA 和视口测试通过，但尚未取得两台真实手机上的图片选择、后台切回、弱网恢复证据。
5. **Cloudflare 免费额度：中。** 活动期间应监控 D1 读写、R2 Class A/B 请求和 Workers 请求量，避免测试数据与正式活动共用资源。
6. **GitHub Actions 提示：低。** Actions 依赖仍显示 Node 20 兼容层弃用提示，目前不影响部署成功，但应在后续维护窗口升级 action 主版本。

## 已执行的速度优化

- 入场字体改为 2.6KB 字符子集，减少首屏阻塞资源。
- 登录响应继续一次返回用户、赛道和活动配置，避免额外初始化查询。
- 任务、广场、排行榜均使用分页或限定查询，图片通过受保护 R2 地址按需读取。
- 保留浏览器图片压缩，避免常规上传接近 Worker 请求体上限。

## 上线建议

先安排 20–50 名真实参与者在 Android 微信和 iPhone 微信各完成一次登录、图片选择、提交、浏览和点赞；确认无授权或返回页问题后，再开放全体。正式开放当天监控错误率和 P95；若上传 5xx 超过 1% 或 P95 连续超过 5 秒，应暂停集中上传并延长提交窗口。
