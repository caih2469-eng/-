# 阶段 10：安全与性能

## 已在本地版本落地

- 所有 `/api/admin/*` 接口统一在服务端校验管理员角色。
- 学生写入接口从会话身份确定用户或队伍，不接受客户端指定其他用户 ID。
- 会话改为 HMAC-SHA256 签名并包含 12 小时过期时间。
- 密码登录时自动升级为 `scrypt` 加盐哈希；新增、编辑和 Excel 导入密码直接保存哈希。
- 登录按来源 IP 与学号组合限流，15 分钟内最多 10 次。
- JSON 请求限制 25MB；图片校验 MIME、扩展格式、文件签名和压缩后大小。
- 文本统一长度限制；页面动态内容统一经过 `escapeHtml`。
- API、HTML、脚本、样式和图片增加 CSP、禁止 iframe、MIME 嗅探、Referrer 与 Permissions Policy。
- 静态路径使用解析后的绝对路径验证，阻止目录穿越。
- 数据库采用单进程写队列、临时文件加原子替换，避免并发请求互相覆盖。
- 数据文件常驻内存并按文件修改时间失效，避免每次请求重新读取和解析整库。
- 排行榜缓存 60 秒，所有写操作后自动失效。
- 广场继续服务端分页；最终截图后台增加 50 条/页和校区筛选。
- 图片继续原生 `loading="lazy"`，上传前在浏览器压缩。

## SQL 安全结论

当前本地程序使用 JSON 数据文件，没有执行 SQL，因此不存在 SQL 注入入口。Cloudflare 正式版迁移到 D1 后必须只使用绑定参数，不拼接用户输入。建议索引见 `migrations/cloudflare-d1-indexes.sql`。

## Cloudflare 免费版部署模型

- Workers Static Assets：宣传页和前端静态资源。
- Workers：鉴权、权限验证和 API。
- D1：用户、队伍、任务、打卡、点赞、浏览及材料元数据。
- 私有 R2：打卡和最终证明截图；通过鉴权 Worker 读取，不开放 `r2.dev`。
- Cache API：仅缓存公开排行榜和公开广场读取，不缓存用户资料或管理员数据。

700 人并不等于 700 个持续连接。按每人每日 10～30 个 API 请求估算为 7,000～21,000 次/日，低于 Workers Free 的 100,000 次/日；活动集中提交时仍需实测。图片必须直接写入 R2，避免 Worker 内存中长时间处理。

## 上线门槛

本地 Node/JSON 版本已完成安全基线，但不能宣称为 Cloudflare 生产数据层。正式上线必须完成 Worker + D1 + R2 适配、设置 `SESSION_SECRET`、执行 D1 迁移、关闭公开对象桶，并进行至少 700 虚拟用户的阶梯压测。
